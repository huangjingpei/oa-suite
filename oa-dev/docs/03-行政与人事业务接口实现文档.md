## 1. 业务领域架构与协同模式

在里程碑 M3 中，基于已就绪的 `oa-framework` 与 `WfEngineService` 工作流调度器，全面完成了两大核心业务领域及文件上传基础设施的服务端实现：

```
                                  ┌───────────────────────────────┐
                                  │      WfEngineService 引擎     │
                                  │ (负责流程实例/待办/加签/履历) │
                                  └──────────────▲────────────────┘
                                                 │ 启动流程 / 状态同步
                 ┌───────────────────────────────┴──────────────────────────────┐
                 │                                                              │
  ┌──────────────────────────────┐                              ┌──────────────────────────────┐
  │     人事与考勤领域 (HR)      │                              │      行政与公文领域 (ADM)    │
  ├──────────────────────────────┤                              ├──────────────────────────────┤
  │ 1. 请假申请 (oa_hr_leave)    │                              │ 1. 统一用印 (oa_adm_seal)    │
  │ 2. 异常补卡 (oa_hr_repair)   │                              │ 2. 红头公文 (oa_adm_redhead) │
  │ 3. 补卡明细 (repair_detail)  │                              │ 3. 档案借阅 (oa_adm_borrow)  │
  │ 4. 打卡流水 (clock_record)   │                              └──────────────────────────────┘
  └──────────────────────────────┘
```

### 1.1 单据与流程无缝挂接标准
所有业务单据采用统一的标准交互机制：
1. **灵活的“草稿暂存”与“立即提交”双轨制**：
   - 当 `isDraft = true` 时，单据仅保存至业务表，`proc_status = 0 (草稿)`，不产生流程实例与待办；
   - 当 `isDraft = false` 时，单据插入后立即自动装配 `ProcessStartDTO` 调用 `WfEngineService.startProcess(...)`，生成流程实例，将单据置为 `1 (审核中)`，并为第一级审批人分发待办任务。
2. **规范化业务流水号生成**：
   - 请假单：`QJ + yyyyMMdd + 4位随机码`（如 `QJ202610271234`）
   - 用印单：`YZ + yyyyMMdd + 4位随机码`（如 `YZ202610275678`）
   - 补卡单：`BK + yyyyMMdd + 4位随机码`（如 `BK202610279012`）
   - 借阅单：`DA + yyyyMMdd + 4位随机码`（如 `DA202610273456`）
3. **单据详情包含打印排版基准字段**：
   - 所有单据详情接口（`getDetail`）直接提供带审批人、申请人、部门、流水号的完整实体，完全满足后续 Vue 3 打印排版组件的脱敏与排版需求。

## 2. 人事考勤领域（HR）接口规格

### 2.1 请假管理 (`/api/hr/leave`)
| 请求方法 | 接口路径 | 说明 | 核心请求体 / 参数 |
| :--- | :--- | :--- | :--- |
| `POST` | `/api/hr/leave/apply` | 提交请假申请 (支持草稿与流程启动) | `leaveType`, `startTime`, `endTime`, `totalHours`, `totalDays`, `reason`, `files`, `auditUsernames`, `isDraft` |
| `GET` | `/api/hr/leave/detail/{id}` | 获取请假单详情 (打印与审阅) | 路径参数 `id` |
| `GET` | `/api/hr/leave/my` | 查询我的请假记录 (分页) | Query `pageNum`, `pageSize` |

### 2.2 考勤打卡与漏卡补卡 (`/api/hr/attendance`)
| 请求方法 | 接口路径 | 说明 | 核心请求体 / 参数 |
| :--- | :--- | :--- | :--- |
| `POST` | `/api/hr/attendance/clock-in` | 员工日常打卡 (支持网页端与移动端定位) | `clockType (ON/OFF)`, `deviceType`, `locationAddress`, `latitude`, `longitude` |
| `GET` | `/api/hr/attendance/my-records` | 查询我的日常打卡流水记录 (分页) | Query `pageNum`, `pageSize` |
| `POST` | `/api/hr/attendance/repair/apply` | 提交考勤异常漏卡补卡申请 (挂接流程) | `reason`, `files`, `auditUsernames`, `details: [{repairDate, repairType, repairSignTime}]` |
| `GET` | `/api/hr/attendance/repair/detail/{id}` | 获取补卡申请详情及漏卡明细列表 | 路径参数 `id` |
| `GET` | `/api/hr/attendance/repair/my` | 查询我的考勤补卡申请单 (分页) | Query `pageNum`, `pageSize` |

## 4. 通用文件上传与离线访问基础设施

为解决原系统强依赖阿里云 OSS、导致脱离云厂商便无法跑通单据附件上传的硬编码痛点，在 `com.graddu.oa.common.controller.FileUploadController` 中提供了高兼容的**本地化附件存储引擎**：

| 请求方法 | 接口路径 | 鉴权要求 | 说明 |
| :--- | :--- | :---: | :--- |
| `POST` | `/api/common/upload` | 需登录 | 采用 `multipart/form-data` 接收图片/PDF/Office 附件，UUID 重命名存储于 `./uploads/`，返回访问相对路径（如 `/api/common/file/a1b2c3d4.pdf`） |
| `GET` | `/api/common/file/{fileName}` | 匿名放行 | 原生流式文件传输，设置 `inline` 响应头，直接支持浏览器图片预览与 PDF 在线预览 |

## 5. 端到端流程联调验证指引（以请假为例）

开发者启动服务后，可在 Swagger 界面（`http://localhost:8080/api/swagger-ui.html`）按以下标准链路完成一次完整的业务单据闭环验证：

```
[步骤1: 员工登录]
POST /api/auth/login {"username": "zhangsan", "password": "123456"}
-> 获取 Token，配置在 Swagger 右上角 Authorize 中

[步骤2: 员工提交请假申请]
POST /api/hr/leave/apply
{
  "leaveType": "PERSONAL",
  "startTime": "2026-10-28 09:00:00",
  "endTime": "2026-10-29 18:00:00",
  "totalHours": 16.0,
  "totalDays": 2.0,
  "reason": "家中有事处理",
  "auditUsernames": ["dev_mgr", "hr_mgr"]
}
-> 返回生成的请假单 ID (如 1789...)，单据状态自动为 1 (审核中)

[步骤3: 主管查阅待办并审批同意]
POST /api/auth/login {"username": "dev_mgr", "password": "123456"}
GET  /api/wf/process/pending -> 查看到来自张三的第1级待办任务
POST /api/wf/process/approve {"taskId": ..., "opinion": "同意请假"}
-> 任务自动流转至下一级 hr_mgr

[步骤4: 人事终审通过]
POST /api/auth/login {"username": "hr_mgr", "password": "123456"}
POST /api/wf/process/approve {"taskId": ..., "opinion": "人事审核通过，已登记假期"}
-> 流程实例自动归档为 2 (通过)，请假单 oa_hr_leave.proc_status 自动同步为 2 (已通过)

[步骤5: 查阅审批履历时间轴]
GET  /api/wf/process/history/{instId}
-> 完整展现从提交、研发经理同意到人事主管终审的全链路时间轴与签名记录
```
