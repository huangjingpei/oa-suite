## 1. 后端工程脚手架架构

### 1.1 核心技术栈构成
为实现“自建纯净轻量工程、零历史冗余包袱”的既定策略，后端工程完全基于最新的企业级技术标准构建：

| 核心组件 | 选型版本 | 承担职责与优势 |
| :--- | :--- | :--- |
| **基础底座** | **Spring Boot 3.2.5 (JDK 17 LTS)** | 现代微服务与单体最优基准，支持虚拟线程与最新 Web 性能特性 |
| **认证与鉴权** | **Sa-Token 1.38.0 (Spring Boot 3 专版)** | 替代过时的 Apache Shiro 与繁重的 Spring Security，轻量无侵入地实现 Token 签发、路由拦截与防水平越权 |
| **持久层持久化** | **MyBatis-Plus 3.5.6 (Spring Boot 3 专版)** | 动态条件构造器、雪花算法主键生成、分页插件与审计字段自动填充 |
| **数据库驱动** | **MySQL Connector J 8.3.0** | 支持 MySQL 8.0+ 现代化连接特性与时区协商 |
| **文档与调试** | **SpringDoc OpenAPI 3 (v2.5.0)** | 替代废弃的 Swagger 2，原生支持 OpenAPI 3.0 规范，提供交互式 `/api/swagger-ui.html` |
| **辅助工具包** | **Lombok + Hutool 5.8.27** | 消除冗余样板代码，提供 BCrypt 密码加密与数据安全处理 |

### 1.2 彻底根治历史架构硬伤
在原 2020 年版工程中，前端通过 `xmysql` 直接裸连底层 MySQL 数据库执行 `INSERT` 与 `UPDATE`，且在审批时使用 `setTimeout(..., 100)` 发起二次状态修改，存在无法挽回的脏写与越权风险。

在本次重构中：
- **服务端强事务收口**：所有审批流转、单据状态变动均在 `@Transactional(rollbackFor = Exception.class)` 数据库事务中原子执行。
- **严格水平越权防护**：审批处理接口（`approve`、`reject`、`addSign`）强制核对当前登录人（`StpUtil.getLoginIdAsString()`）是否为该任务的被指派人（`assignee_username`），任何人无法通过伪造任务 ID 越权审批他人业务。

## 2. 自研轻量工作流引擎（WfEngine）深度设计

针对用户“沿用并重构原项目自研轻量状态机”的决策，新流程引擎通过 5 张领域表支撑起完整的自由审批闭环：

### 2.1 引擎核心实体与流转全景
```
                     【发起流程 startProcess】
                                │
                                ▼
                   ┌──────────────────────────┐
                   │      oa_wf_instance      │ (创建实例: status=1 审核中)
                   │  - current_node: 第1级审批 │
                   │  - current_assignee: 审批人│
                   └────────────┬─────────────┘
                                │ 存储动态审批链条
                                ▼
                   ┌──────────────────────────┐
                   │     oa_wf_free_route     │ (audit_chain: ["dev_mgr", "hr_mgr"])
                   │  - current_seq: 1        │
                   └────────────┬─────────────┘
                                │ 生成首节点任务
                                ▼
                   ┌──────────────────────────┐
                   │        oa_wf_task        │ (status=1 待处理)
                   │  - assignee: dev_mgr     │
                   └────────────┬─────────────┘
                                │
             ┌──────────────────┴──────────────────┐
             ▼ 审批通过 (approve)                   ▼ 审批驳回 (reject)
┌──────────────────────────┐          ┌──────────────────────────┐
│ 1. 当前任务置为 COMPLETED │          │ 1. 当前任务置为 COMPLETED │
│ 2. 写入履历 oa_wf_history │          │ 2. 写入履历 (REJECT)     │
│ 3. 判定加签 / 下一级审批 │          │ 3. 实例与业务单据标为驳回 │
└────────────┬─────────────┘          └──────────────────────────┘
             │
             ├────── 存在加签 ──────► 插入临时加签任务 (TaskType=SIGN)
             │
             ├────── 存在下一级 ────► 任务指派给下一级 (current_seq + 1)
             │
             └────── 流程结束 ──────► 实例状态标为 2 (通过), 业务单据标为 2 (通过)
```

### 2.2 核心业务调度算法说明
1. **自由流程链条动态调度**：
   - 发起人提交时指定有序审批人链条 `auditUsernames: ["dev_mgr", "hr_mgr"]`。
   - 引擎将链条作为 JSON 序列化持久化至 `oa_wf_free_route`，当前流转序号 `currentSeq` 设为 1。
   - 每一级审批人通过后，`currentSeq` 自动自增，若 `currentSeq > auditChain.size()`，判定流程全面办结。
2. **即时动态加签机制**：
   - 审批人在审阅单据时，若发现需要其他专家或领导协助评估，可指定 `addSignUsername`。
   - 引擎会在当前审批节点与下一节点之间插入一个 `TaskType=SIGN` 的加签任务，实例当前审批人临时移交该加签人，待加签人审批通过后，再自动返回原主干链条。
3. **跨表业务状态同步器**：
   - 引擎具备跨表动态状态同步器 `updateBusinessStatus(tableName, businessId, instId, status)`，在审批同意办结、驳回或作废时，自动将业务单据表（如 `oa_hr_leave`、`oa_adm_seal_apply`）的 `proc_inst_id` 和 `proc_status` 保持原子一致。

## 3. RESTful API 接口规格一览

后端统一对外暴露规范的 RESTful 接口，所有接口响应均被封装为标准 `R<T>` 格式：

### 3.1 系统认证与用户模块
| 请求方法 | 路径 | 权限要求 | 接口说明 |
| :--- | :--- | :---: | :--- |
| `POST` | `/api/auth/login` | 匿名开放 | 员工登录获取 Sa-Token 访问令牌 |
| `POST` | `/api/auth/logout` | 需登录 | 安全退出当前会话 |
| `GET` | `/api/auth/profile` | 需登录 | 获取当前登录员工资料、部门与拥有角色 |
| `GET` | `/api/sys/user/options` | 需登录 | 获取所有员工列表（用于审批人下拉选择组件） |
| `GET` | `/api/sys/dept/tree` | 需登录 | 获取组织架构部门树形数据 |

### 3.2 自研工作流引擎核心模块
| 请求方法 | 路径 | 接口说明 | 核心参数/请求体 |
| :--- | :--- | :--- | :--- |
| `POST` | `/api/wf/process/start` | 发起审批申请 | `procKey`, `businessTable`, `businessId`, `title`, `auditUsernames` |
| `POST` | `/api/wf/process/approve` | 审批同意 | `taskId`, `opinion`, `addSignUsername` (选填) |
| `POST` | `/api/wf/process/reject` | 审批驳回 | `taskId`, `opinion` |
| `POST` | `/api/wf/process/add-sign` | 审批中临时加签 | `taskId`, `targetUsername`, `opinion` |
| `POST` | `/api/wf/process/cancel/{instId}` | 发起人作废撤回 | 路径参数 `instId`, Query `reason` |
| `GET` | `/api/wf/process/pending` | 查询我的待办任务 (分页) | Query `pageNum`, `pageSize` |
| `GET` | `/api/wf/process/handled` | 查询我的已办历史 (分页) | Query `pageNum`, `pageSize` |
| `GET` | `/api/wf/process/my-submitted`| 查询我发起的审批单据 (分页) | Query `pageNum`, `pageSize` |
| `GET` | `/api/wf/process/history/{instId}` | 获取流程审批履历时间轴 | 路径参数 `instId` |

## 4. 开发者启动与验证指南

### 4.1 环境准备
- **JDK**：Java 17 LTS
- **构建工具**：Apache Maven 3.9+
- **数据库**：MySQL 8.0+（已提前执行 M1 的 `schema.sql` 与 `seed-data.sql`）

### 4.2 编译与启动
```bash
# 进入后端工程目录
cd E:\OA\oa-suite\oa-dev\oa-backend

# 编译代码
mvn clean compile

# 启动 Spring Boot 后端服务
mvn spring-boot:run
```

### 4.3 浏览器访问在线 API 文档
服务启动后，在浏览器访问：
👉 `http://localhost:8080/api/swagger-ui.html`

可在 Swagger 页面中直接测试 `/api/auth/login`（默认账号 `admin` / 密码 `123456`），获取 Token 并在右上角 Authorize 中配置进行全链路流程测试。
